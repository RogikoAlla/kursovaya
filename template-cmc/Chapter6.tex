\section{Экспериментальное исследование}
\label{sec:Chapter6} \index{Chapter6}

В данной главе описывается методика проведения экспериментов, анализируются полученные результаты и формулируются выводы о сравнительной эффективности реализованных алгоритмов.

\subsection{Методика экспериментального исследования}

\subsubsection{Цели эксперимента}

Основными целями экспериментального исследования являются:
\begin{itemize}
	\item сравнение многопроходного \texttt{FFD} и \texttt{FFLS} по времени выполнения;
	\item сравнение алгоритмов по количеству использованных стадий конвейера;
	\item оценка влияния количества таблиц и количества записей в таблицах на производительность алгоритмов;
\end{itemize}

\subsubsection{Исходные данные}

Для экспериментов были сгенерированы синтетические конфигурации, каждая из которых представляет собой граф зависимостей таблиц (TDG) и параметры таблиц. Конфигурации различались по двум параметрам:

\begin{itemize}
	\item \textbf{Количество таблиц} $N \in \{30, 40, 50, 100, 200, 300\}$.
	\item \textbf{Количество записей в таблице} $E \in \{256, 1024, 4096, 16384\}$ (все таблицы в одной конфигурации имели одинаковое число записей).
\end{itemize}

Для каждой комбинации $(N, E)$ было подготовлено по 20 различных графов зависимостей, отличающихся структурой (количеством и типами рёбер). Таким образом, общее количество тестовых конфигураций составило $6 \times 4 \times 20 = 480$. 

Аппаратная конфигурация (RMT-коммутатор) была зафиксирована в соответствии с описанием V1Model: 
\begin{itemize}
	\item 32 match-action стадии;
	\item 106 блоков SRAM на стадию (ширина 80 бит, глубина 1024 записи);
	\item 16 блоков TCAM на стадию (ширина 40 бит, глубина 2048 записи).
\end{itemize}

\subsubsection{Параметры эксперимента}

Каждый алгоритм запускался на каждой конфигурации 10 раз. Такое количество прогонов необходимо для уменьшения влияния случайных флуктуаций времени выполнения, связанных с фоновыми процессами операционной системы. Измерялись следующие величины:
\begin{itemize}
	\item время выполнения алгоритма (в миллисекундах)
	\item количество использованных стадий конвейера 
\end{itemize}

\subsubsection{Обработка результатов}

Для каждой комбинации $(N, E)$ и каждого алгоритма по 20 конфигурациям и 10 прогонам вычислялись:
\begin{itemize}
	\item среднее арифметическое времени выполнения $\bar{T}$;
	\item минимальное $T_{\min}$ и максимальное $T_{\max}$ значения времени;
	\item среднее количество стадий $\bar{S}$, а также $S_{\min}$ и $S_{\max}$.
\end{itemize}

Усреднение по 10 прогонам позволяет уменьшить влияние «шума» – кратковременных задержек, вызванных внешними процессами. Анализ гистограмм с усами даёт представление о разбросе результатов. Все вычисления производились с помощью скриптов на Python с использованием библиотек \texttt{pandas} и \texttt{numpy}.

На Рис. 1 представлены линейные графики зависимости среднего времени выполнения от количества записей в таблице для разных количеств таблиц.

\begin{figure}[h]

	\caption{Зависимость времени выполнения от количества записей}
	\label{fig:time_by_entries}
\end{figure}

Наблюдения:
\begin{itemize}
	\item С ростом количества таблиц время выполнения обоих алгоритмов увеличивается, что ожидаемо.
	\item Для малого числа таблиц (30, 40, 50) разница между алгоритмами незначительна и может составлять доли миллисекунды; в этих случаях \texttt{FFD} иногда оказывается быстрее, иногда медленнее – это можно объяснить случайными вариациями порядка обработки.
	\item При $N \ge 100$ преимущество \texttt{FFLS} становится отчётливым. Например, при 300 таблицах и 4096 записях \texttt{FFLS} работает примерно в 2–3 раза быстрее многопроходного \texttt{FFD}.
	\item Увеличение количества записей (размера таблиц) приводит к росту времени выполнения, особенно заметному для \texttt{FFD}, так как многопроходный алгоритм требует большего числа итераций при разрезании крупных таблиц.
\end{itemize}

\subsubsection{Результаты сравнения по количеству стадий}

На Рис. 2 приведены линейные графики зависимости среднего числа стадий от количества записей.

% Вставка графика plot_stages_by_entries.png
\begin{figure}[h]
	\centering
	\includegraphics[width=0.9\textwidth]{plot_stages_by_entries.png}
	\caption{Зависимость количества стадий от количества записей}
	\label{fig:stages_by_entries}
\end{figure}

Ключевые выводы:
\begin{itemize}
	\item При фиксированном количестве таблиц увеличение числа записей не сильно влияет на количество стадий. Это объясняется тем, что при разрезании таблицы распределяются по последовательным стадиям, но общее число стадий в основном определяется структурой графа зависимостей, а не абсолютным размером таблиц.
	\item С ростом количества таблиц от 30 до 300 количество стадий возрастает примерно линейно. \texttt{FFLS} и многопроходный \texttt{FFD} показывают почти одинаковое среднее число стадий (отличие не превышает 5\%).
	\item На малых количествах таблиц (30–50) \texttt{FFD} иногда даёт чуть более плотную упаковку,поскольку FFD всегда пытается поместить крупные таблицы первыми, он может уменьшить число стадий на небольших графах. Однако при $N \ge 100$ различия становятся незначительными.
\end{itemize}

\end{itemize}

\subsection{Погрешности}

Как было отмечено в методике, время выполнения алгоритмов может подвергаться кратковременным задержкам из-за фоновых процессов операционной системы. Эти задержки проявляются в виде отдельных выбросов (например, время одного прогона может быть в 1.5–2 раза выше среднего). Для снижения их влияния используется усреднение по 10 прогонам. Выбросы не удаляются, так как они являются частью реальных условий исполнения на обычном компьютере; их учёт позволяет получить более консервативную оценку производительности.
