\subsection{Горизонтальное разрезание таблиц}
\label{sec:slicing-implemented}
Если таблица не помещается целиком ни на одной допустимой стадии, программа размещения может разбить её на несколько фрагментов с последующим согласованным выполнением (horizontal table split). Это увеличивает число узлов TDG и усложняет проверку зависимостей, но позволяет избежать тупика при жёстких лимитах SRAM/TCAM. В реализации модуль горизонтального разрезания вызывается планировщиком, когда ни одна допустимая по TDG стадия не содержит достаточной остаточной квоты памяти при выполнении предиката допустимости. Сплиттер порождает фрагменты с обновлёнными требованиями ресурсов и дополнительными ограничениями предшествования так, чтобы части одной логической таблицы выполнялись последовательно с согласованием ключей; политика дробления задаётся конфигурацией и не затрагивает интерфейс остальных модулей (см.~раздел~\ref{sec:Chapter5}).

\item[Ограничение последовательности фрагментов] — при горизонтальном разрезании таблицы все её фрагменты должны располагаться в стадиях с номерами, образующими строго возрастающую последовательность без пропусков: \( s_1 < s_2 < \dots < s_k \).

    \item[Ограничение целостности match-зависимости при разрезании] — если таблица \( t_i \) (предок) разрезана на фрагменты, а таблица \( t_j \) (потомок) связана с \( t_i \) match-зависимостью, то все фрагменты \( t_i \) должны быть размещены в стадиях, строго меньших, чем все фрагменты \( t_j \): \( \max \phi_{\text{frag}}(t_i) < \min \phi_{\text{frag}}(t_j) \).

\subsection{Многопроходный FFD}
Многопроходная реализация FFD строится как управляющий цикл над одношаговым размещением таблицы. Перед каждым проходом таблицы упорядочиваются по убыванию выбранной меры ресурсоёмкости; для текущей таблицы последовательно перебираются номера стадий, начиная с минимально допустимого согласно TDG. Для пары (\emph{таблица}, \emph{стадия}) проверяются: размещение всех предшественников и типы зависимостей (включая ограничения «не в одной стадии» для match и обратной match-связи), совместимость с уже размещёнными на стадии таблицами, суммарная занятость SRAM/TCAM. При успехе таблица фиксируется; при неудаче после полного перебора стадий либо увеличивается число стадий-приёмников ресурсов, либо выполняется разрезание (см.~п.\,\ref{sec:slicing-implemented}). После завершения прохода выполняется анализ таблиц, оставшихся без размещения: при наличии таковых возможны следующий проход с обновлённым графом (после сплитов) или изменение параметров упорядочивания вплоть до исчерпания лимита итераций. Таким образом, многопроходность охватывает повторную подачу множества таблиц после частичных решений или дробления до стабилизации результата.

\subsection{FFLS}
Алгоритм FFLS (First Fit by Level and Size) в реализации сочетает топологический порядок с жадным first fit по стадиям. На входе вычисляются уровни вершин TDG (или эквивалентная топологическая стратификация); таблицы внутри каждого уровня упорядочиваются по убыванию ресурсоёмкости, после чего к каждой применяется тот же предикат допустимости и правило первой подходящей стадии, что и в FFD. Такой порядок согласует обход графа с направлением зависимостей и задаёт понятный эталон для сравнения с FFD без явного включения топологических уровней в правило упорядочивания последнего.
